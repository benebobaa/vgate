# CLI Reference

Every command supports `--json` (machine-readable `{ command, ok, exitCode, summary, data, next }` envelope), never prompts interactively, and emits actionable `next` steps.

Run `vgate help --json` at any time for the live structured catalogue.

## Global Flags & Exit Codes

| Flag               | Default               | Meaning                                             |
| ------------------ | --------------------- | --------------------------------------------------- |
| `--json`           | `false`               | Emit one JSON envelope on stdout                    |
| `--quiet`          | `false`               | Suppress streamed stderr logs (implied by `--json`) |
| `--service <name>` | `$SERVICE`            | Target service (or the sole configured service)     |
| `--env <name>`     | `$TEST_ENV` / `local` | Target environment in `service.yaml`                |
| `--root <dir>`     | nearest `vgate.yaml`  | Project root override                               |

| Exit Code | Meaning                                                                                                         |
| --------- | --------------------------------------------------------------------------------------------------------------- |
| `0`       | Success (`guard`: `auto`; `decide`: `merge`)                                                                    |
| `1`       | Verification failed or requires human approval (`guard`: `needs-human`; `decide`: `needs-approval` / `blocked`) |
| `2`       | Invalid usage, unknown command, unknown flag, or strict schema error                                            |
| `3`       | Not ready (missing dependency, base ref, stack, or runtime problem)                                             |

## Setup & Agent Interop

| Command                                                                                                                                                              | Description                                                                                                                                                                                                                               |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `vgate init [--service <name>] [--ci github\|gitlab] [--agents <list>] [--packs <list>] [--force]`                                                                   | Create `vgate.yaml` pinned to this binary version, service skeleton, `.gitignore` entries, agent skills, and optional CI workflows.                                                                                                       |
| `vgate doctor [--service <name>] [--fix]`                                                                                                                            | Check required host tools and container runtime; `--fix` unpacks/hydrates the versioned runtime into `~/.cache/vgate/`.                                                                                                                   |
| `vgate skills list\|install [<skill>...] [--dir <dir>] [--agents all\|agy,claude,cursor,codex,opencode,pi,omp,grokbot] [--packs core,rigor,scale\|full] [--dry-run]` | Inspect or project canonical `vgate-*` skills (auto-generating `vgate-verify` from `vgate.yaml` + `features/`) without clobbering existing user files.                                                                                    |
| `vgate mcp`                                                                                                                                                          | Start `vgate` as a stdio JSON-RPC 2.0 MCP server exposing core commands (`vgate_lint`, `vgate_gate`, `vgate_guard`, `vgate_decide`, `vgate_verify`, `vgate_doctor`, `vgate_services`, `vgate_maturity`, `vgate_metrics`, `vgate_status`). |

## Guardrails, Verification & Merge Decision

| Command                                                                                                                   | Description                                                                                                                                                                                                                                                                                    |
| ------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `vgate lint [--test] [--config <file>] [--ratchet <file>] [--update-ratchet] [--skip-native] [--files a,b]`               | Run polyglot `guardrails.yaml` checks (import boundaries, banned patterns with `replaceWith`, comment caps, `.vgate-ratchet.json`, presets, native linters, `AGENTS.md` rule table). `--test` verifies rule fixtures; `--config`/`--ratchet` allow trunk-pinned CI execution.                  |
| `vgate gate --service <name> [--steps a,b]`                                                                               | Run deterministic verification steps (`selftest,typecheck,lint,test,contract,coverage`) and write `reports/verdict.json`.                                                                                                                                                                      |
| `vgate guard [--service <name>] --base <ref>`                                                                             | Compare expectations (contract, inventory, `service.yaml`, known failures, test assertions, `guardrails.yaml`, `.vgate-ratchet.json`, `.vgate-quarantine.yaml`, `formal:`, judge machinery) against `--base`. Omit `--service` for repo-level `_repo` guard.                                   |
| `vgate affected --base <ref>`                                                                                             | Compute changed services (via `paths:` in `service.yaml`) and deleted services relative to the merge base.                                                                                                                                                                                     |
| `vgate risk --base <ref>`                                                                                                 | Compute PR risk tier (`low` \| `medium` \| `high`) using `vgate.yaml` `risk:` rules, UX/UI taste globs (`uxPaths` / `DEFAULT_UX_PATHS`), and built-in `JUDGE_RISK` protections.                                                                                                                |
| `vgate decide --base <ref> --evidence <dir> [--details-url <url>]`                                                        | Produce the final stacked verdict (`merge` \| `needs-approval` \| `blocked`), reading policy/guardrails presence from trunk (`mergeBase`), verifying `vgate.signature/1` envelopes fail-closed, and emitting `reports/decision.json`, `reports/decision.md`, and `reports/review-bundle.json`. |
| `vgate verify --base <ref> [--mode auto\|full\|single\|skip] [--verifiers 1] [--author-harness <h>] [--author-model <m>]` | Run independent cross-vendor live-app verification (defaults to 1 verifier), stacked fail-closed over deterministic gates and signed when `VGATE_SIGNING_*` is set.                                                                                                                            |

## Services, Deploy Safety & Learning Loop

| Command                                                                                             | Description                                                                                                                 |
| --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `vgate services`                                                                                    | List configured services and `servicesDir`.                                                                                 |
| `vgate up \| down \| status --service <name>`                                                       | Manage local service dependency stacks.                                                                                     |
| `vgate reset --service <name> --yes`                                                                | Destructively wipe and re-seed local service test data (refused without `--yes`).                                           |
| `vgate inventory --service <name> [--write]`                                                        | Generate a test-plan skeleton (`inventory.skeleton.yaml`) from OpenAPI specs.                                               |
| `vgate compat [--service <name>] [--environment <env>]`                                             | Verify OpenAPI backwards compatibility against deployed environments.                                                       |
| `vgate config-check [--service <name>] [--environment <env>] [--base <ref>]`                        | Verify required config keys exist in target environments without reading secret values.                                     |
| `vgate migrations --service <name> --base <ref>`                                                    | Lint SQL migrations (`squawk`), round-trip `up`/`down` in a sealed DB, and test deployed merge-base code on the new schema. |
| `vgate mutate --service <name> --base <ref> [--budget 20] [--timeout 10m] [--all-tests]`            | Run diff-scoped mutation testing in a scratch worktree against `policy.mutationScore`.                                      |
| `vgate smoke --service <name> --env <env>`                                                          | Run read-only smoke verification against a deployed environment (refuses non-read-only calls unless allowlisted).           |
| `vgate canary --service <name> --env <env> [--for 10m] [--every 30s] [--on-fail '<cmd>'] [--smoke]` | Poll deployment canary metrics and run rollback once on breach.                                                             |
| `vgate drift --env <env> [--service <name>] [--dependency <name>]`                                  | Probe live dependency sandboxes against vendored contracts.                                                                 |
| `vgate incident add\|report [--service <name>] ...`                                                 | Turn escaped production bugs into permanent `[INC-<n>]` regression tests and track catch rate.                              |

## Governance, Proof, Metrics & Experimental Factory

| Command                                                                               | Description                                                                                                                                                                                                                                            |
| ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `vgate maintain [--service <name>]`                                                   | Read-only Feature Map drift audit (`clean` \| `changed` \| `blocked`).                                                                                                                                                                                 |
| `vgate formal [--verify-mutation]`                                                    | Run configured Tier-2 formal specs (TLA+, Lean, Bombadil) with sync-commit drift & mutation checks.                                                                                                                                                    |
| `vgate statechart --input <spec.tla> [--output <file.mmd>] [--max-arrows 20]`         | Render a best-effort Mermaid state diagram from a TLA+ or DOT spec.                                                                                                                                                                                    |
| `vgate benchmark --baseline "<cmd>" --candidate "<cmd>" --limiter "<why>" [--runs 5]` | Run alternating A/B performance trials with range-overlap rigor checks.                                                                                                                                                                                |
| `vgate eval --spec <eval.json>`                                                       | Run blinded comparative skill evaluations with transcript adherence checks.                                                                                                                                                                            |
| `vgate ship patch-id\|rebase-check\|plan`                                             | Merge-queue helpers: semantic Patch-ID calculation, 3-rebase ceiling check, and bottom-up stack planning.                                                                                                                                              |
| `vgate maturity [--require 1..5]`                                                     | Evaluate 5-phase readiness (Phases 1–3 advisory; Phases 4–5 require out-of-band `VGATE_ALLOW_AUTONOMY=1`).                                                                                                                                             |
| `vgate metrics record\|report [--days 30] [--format text\|json\|html\|otel]`          | Append or export the local-first 5-KPI engineering ledger (`.vgate/metrics.jsonl`).                                                                                                                                                                    |
| `vgate factory serve\|status\|audit\|dispatch` · `vgate stop` · `vgate resume`        | **Experimental primitives** for Layer 1 outer-loop orchestration: untrusted signal framing, secret-stripped `DockerSandbox` (`--network none`), `.vgate/STOP` zero-writes switch, and side-effect trail logging (not yet an autonomous worker daemon). |
| `vgate help` · `vgate version`                                                        | Print command catalogue or binary version.                                                                                                                                                                                                             |
